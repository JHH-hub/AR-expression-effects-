# Part 2｜微笑落雨，大笑烟花

Live Demo：https://facefx.pxlsan.cn/

Public Source：https://github.com/JHH-hub/AR-expression-effects-

## 1. 产品定义

开启摄像头后，保持自然表情约0.9秒校准；微笑带来连续雨幕，大笑触发烟花并按节奏追加连击。提供表情强度反馈、重新校准与手动烟花按钮。手动按钮只用于预览，不能作为识别验收证据。观众数与评论框为场景示意，不连接真实直播业务。

一次 FaceLandmarker 推理同时取得面部关键点和 blendshape。嘴角相对基线的上扬是必要证据，眼周收缩仅增强已有笑意，张嘴强度参与大笑门控。EMA、迟滞和连续帧确认用于减少闪烁，不能承诺对所有人精准分类。

关键点映射到镜像、cover后的屏幕坐标，拟合二维椭圆碰撞体。检测粒子相对上一帧与当前头部的整段路径，覆盖高速穿越和头部主动移动；在运动边界的坐标系中按法线反弹。椭圆尺寸变化采用归一化路径近似，尚不覆盖完整三维遮挡与头发轮廓。

只有新的视频识别结果才能推进校准、连续帧确认和烟花触发；超过250毫秒没有新结果时，取消待触发烟花、关闭头部碰撞体，雨量逐渐回落。切到后台立即暂停并清除待触发事件。短时丢脸后重新识别才恢复互动。

## 2. 性能与取舍

WebGL2 将粒子位置/速度和寿命等状态分别存入 RGBA16F 纹理，通过 ping-pong FBO 更新；每侧两张，共四张状态纹理，另有摄像头及辉光纹理。减少 CPU 粒子循环不代表零成本，GPU 填充、纹理带宽及同步人脸推理仍需预算。

HIGH/MID/LOW 容量为65536/25600/9216，雨槽位均为20%，DPR上限为1.5/1.25/1.0，LOW隔帧推理。FPS使用真实墙钟时间，物理步长单独钳制到50ms。低于46 FPS降档，高于56 FPS升档，切档后冷却2.5秒。容量上限不是活跃粒子数，也不是帧率承诺。

WebGL初始化或初次FBO分配失败时，换用新canvas启动Canvas2D，以较少粒子保留交互。模型或渲染启动失败释放摄像头；页面隐藏暂停推理和渲染，离开页面停止媒体轨道。摄像头帧在本地处理，模型与WASM首次加载仍依赖外部CDN。

渲染器诊断实测（2026-10-08）：Windows、RTX 4090、Edge 154无头模式，390×540 CSS像素，HIGH档、80%雨量、每520毫秒一轮烟花、头部左右移动，连续180秒。平均164.9 FPS，帧间隔P95为6.2毫秒，P99为6.3毫秒，GL错误为0。测试不含摄像头上传和人脸推理，也不代表低端设备性能；完整互动的帧率与推理耗时需在真人验收时记录。容量为65536，不表示这些粒子始终全部活跃。

## 3. Vibecoding 复盘（含 Prompt，不超过200字）

最大陷阱是眼周收缩被AI当成独立笑意：嘴角为0、张嘴0.9、眯眼0.8时，两秒触发4次烟花。我增加嘴角门控，并禁止旧视频帧推进表情状态。纠偏Prompt：“嘴角上扬必须是笑意的必要条件；用眯眼张嘴输入复现误触发，修复后同时验证正常大笑保留；没有新识别结果时不得继续触发。”修复后该反例为0次，正常大笑和视频停帧回归通过。

## 4. 验收范围

目标验收环境为Windows上的Chrome或Edge。自动检查已通过22项逻辑回归，包含30/60Hz表情信号、失脸、重校准、重复帧、停帧、渲染降级、低帧率监控以及连续碰撞；增加中等张嘴笑意、弱笑意伴随张嘴变化、单帧张嘴峰值的检查。浏览器中WebGL2和Canvas2D分别渲染90帧通过；直接回读GPU状态确认高速粒子反弹、移动头部推动粒子。Edge 154的模拟摄像头已成功授权、加载模型并启动GPU推理；这项检查不代替真人微笑、大笑准确率。

首次真人体验反馈：微笑后小雨持续偏久，大笑略难触发，其他体验可以。依据这次反馈，20261008b将雨量回落半衰期从1.35秒缩短至0.32秒，大笑进入门槛从0.30降至0.26，保留嘴角门控、平滑和连续帧确认。调整后的手感待再次体验；尚未取得摄像头型号、具体浏览器版本、逐项误触发统计和3分钟完整互动性能数据。手机兼容性暂不作为已通过结论。
